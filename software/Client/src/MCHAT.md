# MCHAT - MSX Free Chat

An IRC chat for the MSX, in the same `#msxpi` channel as the PChess lobby
(PChess game traffic is hidden). One `MCHAT.COM` (about 49 KB in memory,
the image ends near 0xC4D0; with INL loaded the TCP/IP link needs 768 bytes of stack
below 0xC806, so every byte counts - check with `KEEPMAP=1 make mchat` and
`target\mchat.map` (`s__HEAP`)) runs on MSX1 and MSX2 and over two links:

    mchat [/1] [/t] [nick]

| Switch | Meaning |
|---|---|
| (none) | MSXPi server link; the screen follows the machine |
| `/1` | use the MSX1 screen (SCREEN 2) even on an MSX2 |
| `/t` | TCP/IP UNAPI link (InterNestor Lite, GR8NET, ObsoNET...) instead of the MSXPi server |

The screen is SCREEN 2 on an MSX1 (51 columns, 4x8 font) and SCREEN 6 on an
MSX2 (85 columns, BIOS font, 4 colours). The MSX2 is recognised by asking the
BIOS for SCREEN 6. `/screen` switches between the two while running (MSX2
only). Note that openMSX's Canon V-25 is an MSX2.

## Using it

| Key | Action |
|---|---|
| text, RETURN | say it in the current room, or run a `/command` |
| TAB, RIGHT / LEFT | next / previous room (tabs on the top row) |
| UP / DOWN | read older / newer messages |
| HOME | back to the latest message |
| ESC, `/quit` | leave and disconnect |

Commands: `/screen`, `/nick N`, `/msg N TEXT` (private), `/join #room`,
`/part`, `/me TEXT`, `/who`, `/topic`, `/help`. A room tab changes colour when
it has unread messages. Private messages arrive in the room you are looking
at, in yellow. The left panel lists the users of the current room (`@`
operators, `+` voiced).

## The two links

**MSXPi server** (`Server/Python/src/msxpi_chat.py`, command `mchat`): a
subclass of the PChess `IRC` class (connection, TLS, SASL) with a multi-room
chat reader. It keeps 4 rooms, 400 rows of scrollback each and the user lists,
and wraps lines to the width the client announces, so the MSX stores almost
nothing; when the width changes (`/screen`) the history is wrapped again.
Settings come from `msxpi.ini`: the PChess IRC ones (`IRCADDR`,
`PCHESSIRCPORT`, `IRCTLS`, `IRCACCOUNT`, `IRCPASSWORD`, `IRCNICK`) and
`MCHATROOM` (first room, default `#msxpi`). Packet layouts are in the module
docstring. Tests: `Server/Python/tests/test_chat.py`.

**TCP/IP** (`mchat_local.c`): the same server in C inside the program, over
plain TCP (no TLS or SASL on a Z80; the server must accept port 6667).
Memory is smaller: 3 rooms of 32 rows and 32 users each, and changing the
screen width clears the history. The UNAPI layer is copied from
`pchess_tcp.c`. On an MSX1 run `MSR I` and `INL I` first. Settings are in
`MCHAT.INI` in the current directory: `IRCADDR` (default `irc.libera.chat`),
`IRCPORT` (6667), `IRCNICK` (`msxXXXX`), `MCHATROOM`.

## How it is built

- `mchat.c` is the program; it draws only through `mchat_ui.h`, in character
  cells, and never touches the VDP. Commands go through `xchg()`, which sends
  them to the MSXPi server or to `local_exchange()`, and both answer with the
  same 256-byte packets.
- Display backends, both in the binary, chosen by `ui_mode`:
  `mchat_ui_s6.c` repaints the changed span of a text row (pairs of cells, 3
  bytes a pair, an assembly kernel) with the BIOS font on a 6
  pixel pitch, and scrolls the log with one HMMM of the command engine; its four colours are black, white, yellow and blue, so own
  lines are plain white and system lines blue. Colour 0 must be shown, not
  transparent (R#8 bit 5), or the backdrop's stripes show through.
  `mchat_ui_s2.c` uses SCREEN 2 as a bitmap with a software 4x8 font on a 5
  pixel pitch (`mchat_font4x8.h`, generated by `Client/tools/gen_mchat_font.py`).
  Colours are per 8-pixel tile, so styles change only at multiples of 8
  columns; `ui_side` (8) is where the user list ends. Scrolling the log
  copies the pattern and colour tables of its tiles in VRAM. A SCREEN 7 or
  text backend only has to provide the functions in `mchat_ui.h`.
- Only what changed is drawn (`draw_all()`): the user list when `side_dirty`,
  the input line from the first changed character, the log window by row
  identity (`drawn_abs[]`, `rstale[]`; `top` moving by less than a window
  becomes `ui_scroll()` plus the vacated rows). `ui_flush()` stops when a key
  is waiting and the main loop finishes it later. The two backends share one
  shadow buffer, `ui_mem`. Design and measurements: `documents/MCHAT-UI-HANDOVER.md`.
- No C runtime start-up: uninitialised globals are not zeroed, so `main()`
  clears them.

## Build and test

`make mchat` from `software\` (about a minute). End-to-end tests in openMSX
against a local IRC fixture and a second user, decoding VRAM with the
program's own fonts (public and private rows, user list, second room, TAB,
scrollback):

    python Client\tests\mchat_openmsx.py [path\to\mchat.com]                  MSXPi link, SCREEN 2 (Canon V-25, /1)
    set MCHAT_MACHINE=msx2 & python Client\tests\mchat_openmsx.py ...         SCREEN 6 and /screen (FS-A1WSX)
    set MCHAT_LINK=tcp & set MCHAT_FORCE1=1 & python Client\tests\mchat_openmsx.py ...   TCP/IP over INL

The TCP/IP test needs the Windows TAP set up for the PChess TCP/IP test
(MSX at 192.168.99.2, this PC at 192.168.99.1) and port 6667 free.
